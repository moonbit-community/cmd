# Runtime test index

Schema 3 retains case identities, aliases, executable selections, platform
applicability and release policy. It does not register individual Moon package
tests or declare change coverage, evidence obligations or source fingerprints.

`entries` supplies stable IDs used by command fixtures, scenarios, cohorts,
metadata and benchmark references. `release_commands` owns package names,
supported options, comparison profiles, policy sensitivity, releasability and
selected release case IDs. Versions are read from the command `moon.mod` files.

Validation rejects duplicate or empty identities, invalid source selections,
unknown platforms and malformed release metadata. The index is not a passing
test report. Actual assertions determine pass, failure and explicit rejection.

Add or update JSON cases and the applicable index entries together. Stateful
behavior stays in MoonBit scenario functions. Package tests are discovered and
executed by Moon without a second per-test source binding system.

The separate [finite evidence ledger](../proofs/README.md) binds manually reviewed
catalog facets to actual exact contracts and typed scenario assertions.
`scenario-proofs.json` owns reviewed expected values and observation dimensions;
scenario pass tags alone cannot qualify a facet. The generated
[remaining work index](coverage-gaps.md) distinguishes new activated fixtures or
observers from assertion upgrades on existing fixtures. It is a dated finite
review, not a general compatibility or performance claim.

Historical registry snapshots retain their original schemas. The current
index does not backfill them, verify old sources or reconstruct old artifacts.

## Local regression quality gate

`case-quality.json` is generated by `tests/case_quality.mbtx` and binds every
current JSON definition to its source hash and executing assertion kind. The
runner validates the complete inventory before platform skips or selections.
Exact bytes, complete structured/runtime observers, explicit scenario dispatch
and finite nonzero diagnostic contracts are distinct forms of local evidence;
a label, fragment without a rejection reason or differential-only expectation
cannot qualify. Linux pinned-oracle comparison is additional evidence.

Duplicate-stimulus checks retain argument order, input bytes/templates, files,
environment, platform, timing and actual scenario dispatch. Assertion strength
and display names cannot manufacture distinct ordinary invocations. When
consolidating, combine independent assertions and preserve all aliases and
oracle routes. Imported rg records keep all original names and values while
executing each engine-specific unique specification once. These gates constrain
the finite fixtures; they do not prove complete feature activation or upstream
compatibility.
