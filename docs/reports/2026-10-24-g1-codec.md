# G1 codec development evidence

Unpublished candidates: `cli/core@0.8.0` and
`cli/{gzip,gunzip,zcat}@0.1.2`. No package was published. Reader-based decoding
and the remaining G2 work are still open.

The private encoder uses 32 KiB LZ history, 3–258 byte matches, canonical
length-limited Huffman codes and complete stored/fixed/dynamic block costs.
Levels 1–9 change search effort; immutable literal tokens are reused, and
stored payloads use the public byte buffer's bulk write. No FFI or host encoder
implements a command.

## Correctness and size

The 24 gzipops tests pass on Native and Wasm. They include an independent fixed
stream, stored LEN/NLEN/alignment boundaries, Huffman/RLE properties, full-window
matches, multi-block reuse, levels and gzip envelopes. The public API adds only
the optional compression level to `encode`.

The three frontends' 12 registered GNU differential cases pass on each backend,
including all-level/alias decoding and the existing member/header cases. The
existing immutable semantic oracle supplies GNU gzip 1.14. Reports are under
`/private/tmp/cmd-g1-selected-20261024/oracle-{native,wasm}-amd64/`.

The final direct Native/Wasm/GNU matrix contains four 8 MiB corpora and all nine
levels: 432 compression calls and 864 successful independent decoder checks.
Every decoded byte matches the input. Both backends meet the 1.05x same-level
GNU size limit on the compressible corpora. Entropy output adds 1,300 bytes to
8,388,608 input bytes, below the 0.1% overhead limit.

| Corpus, default level 6 | Native ms | Direct Wasm ms | GNU ms | Project bytes | GNU bytes |
| --- | ---: | ---: | ---: | ---: | ---: |
| Repeated 32-byte record | 40.58 | 148.42 | 12.30 | 20,487 | 20,380 |
| Repeated 32,000-byte block | 44.08 | 183.34 | 13.12 | 93,213 | 93,411 |
| Repeated 32,768-byte block | 44.31 | 183.55 | 113.89 | 93,974 | 8,389,906 |
| Continuous entropy | 181.79 | 411.58 | 116.64 | 8,389,908 | 8,389,906 |

GNU gzip 1.14 searches at most distance 32,506. The 32,768-byte repetition
therefore exercises the project's full window; its GNU result is not a general
speed comparison. The record is `0123456789abcdef0123456789abcde\n`.
Entropy uses xorshift32 seed `0x6d2b79f5`, shifts 13/17/5 and each state’s high
byte; window corpora repeat the corresponding first block.

These are macOS arm64 development observations: one warmup and three measured
calls per side/level, with rotating order. Moon/moonrun are 20261021,
moonc is 0.10.17, and GNU gzip is native 1.14. Timing includes process startup,
compression, output and exit; decoding and complete byte comparison are outside
the clock. Direct Wasm results are not published MoonX delivery acceptance.
The selected performance target remains unmet; formal 105-pair delivery and
release gates remain open.

## Encoder memory

For 8 MiB and 128 MiB repeated inputs, `/usr/bin/time -l` reports Native peak RSS
of 3,735,552 and 3,784,704 bytes, respectively. Direct Wasm reports 23,822,336 and
25,739,264 bytes, including moonrun. GNU decodes all four captures to the complete
original bytes. These two observations support bounded encoder storage; they
do not establish a decoder memory bound.

Raw matrices, all trials, the temporary pure MoonBit driver, corpus preparation
and memory observations are retained in
`/private/tmp/cmd-g1-implementation-20261024/`; `observations-*-final` is the final
matrix. Earlier runs remain separate and are not substituted for final results.
