# ADR-0008: Streaming JSON Inputs and Lexical Bindings

Status: Accepted
Date: 2026-09-05
Updated: 2026-10-24
Revision: Retain the JSON/TZif and gzip decisions; record the unpublished parsed matcher and sed instruction loop, including GNU candidate/register selection and pending acceptance gates.

## Target and decision

Frame consecutive top-level JSON values, retain earlier output before later parse errors, and implement -s/-R/-n/-e CLI semantics. Use moonjq 0.2.0 public lexical AST bindings for --arg/--argjson, preserving strings/interpolation and allowing inner shadowing. jqlog retains its separate JSONL contract.

Released moonjq 0.2.0 repairs tostring/tojson but still returns null for string
slices. A shared public-AST adapter lowers read slices through Unicode scalar
arrays, recursively including filter/function bodies, and raises on invalid
input types. Assignment/path operands retain their location AST. Do not patch
dependency caches, substitute query source text, vendor the entire evaluator,
or invoke host jq. Cost: maintain an AST adapter tied to the released enum;
remove it when an upstream release passes the nested/open/negative/Unicode,
optional/error and assignment regressions. No full jq grammar claim follows
from fixing these operations.

Implement explicit `-C` ANSI output and `-M` suppression in MoonBit, including
compact/pretty output, nested values and `JQ_COLORS` parsing. When both options
are present, `-M` wins as in jq 1.8.2. Raw string output remains raw. Automatic
terminal coloring remains unavailable until a released public isatty API can
distinguish terminals reliably; character-device classification is insufficient.

## Alternatives and compatibility cost

The earlier 0.1.0 command candidates share pure MoonBit `bytere`, `checksum`, and
`gzipops` packages in core 0.3.0. MD5/SHA-1/SHA-512 update incrementally, including
padding/block-boundary regressions. Byte views retain NUL and malformed UTF-8;
regex matching uses an explicit C-byte profile with unsupported constructs
rejected. Full locale/regex grammar remains project work, not an async blocker.

The current core 0.8.0 candidate parses BRE/ERE once into a private byte program.
Ordinary matching uses ordered Thompson threads; `find_span` omits capture tags
when no backreference can observe them. `find` retains capture spans and creates
strings only for the chosen result. Backreferences retain distinct full states
on an explicit stack; capture-bearing searches can require exponential resources.
There is no hidden product step limit. Grep's syntax and ASCII case-insensitive
options preserve grammar and original captured bytes instead of rewriting source.

Grep's input cursor scans each byte once and retains immutable block views.
Only records spanning chunks and the requested before-context need retained
storage; output uses a 64 KiB public buffered writer. Fixed patterns are compiled
to bytes and share one leftmost-longest search with ASCII folding and word
boundaries. `-q` and `-l` can finish before EOF. Binary classification occurs on incoming chunks,
preserving earlier text before a later NUL. Input errors flush completed output
and the last partial record; a failed output write is not retried. The longest
record and requested context can still grow, so this is not a fixed RSS cap.

Sed's unpublished 0.2.0 candidate compiles groups and labels before opening input,
then uses a PC, hold space, substitution state and append queue. A streaming cursor
retains a bounded input chunk and current record; script-controlled spaces can grow.
Lazy `$` inspection preserves unreachable-operand and partial-error behavior.
In-place replacement remains ADR-0004 work. Repeated nullable captures now use
GNU candidate selection followed by capture-register restoration, including
counted repeats, nested groups and multiple references. Independent GNU
comparisons match all 1,095 applicable development cases; three oracle faults
remain recorded separately. This replaces the earlier compile-time restriction.
The `is_match` predicate performs candidate pruning without restoring output
registers, matching GNU csplit and sed address calls. Grep spans and expr/sed
capture results retain register selection; these calls can differ on ambiguous
repeated captures.
See the
[workspace support record](../compatibility.md#workspace-matcher-and-sed-candidates)
and [current evidence](../reports/2026-10-24-s-matcher-sed.md). Retain independent
GNU cases across adjacent bounds, empty/nonempty inputs, nested groups, multiple
references and unanchored searches. Full GNU/POSIX grammar, three-platform,
published and performance acceptance remain separate from local comparisons.

Keep the pure RFC 1951 inflater: a public Decoder adapter alone could not
preserve output before truncated trailers. The unpublished 0.1.2 workspace now
uses a private pure MoonBit encoder with 32 KiB LZ history, 3–258 byte matches,
length-limited canonical Huffman trees and complete stored/fixed/dynamic bit-cost
selection. It processes 64 KiB chunks with bounded history and per-chunk tokens;
an open Huffman block can span chunks. Levels `-1`–`-9` change search effort,
defaulting to six; `--fast`/`--best` alias one/nine and the last level wins.
All three frontends accept levels and ignore them while decoding or testing.
Published 0.1.1 remains the frozen stored-block profile. G1 codec tests passed
24/24 on Native and Wasm. The [G1 development report](../reports/2026-10-24-g1-codec.md)
records all-level GNU 1.14 roundtrips, passing selected size limits, direct
timings and encoder memory observations. Published MoonX and the selected
performance target remain open. Compare decoded bytes and error behavior,
not exact GNU compressed bytes. The workspace decoder now shares one Reader
cursor across headers, blocks, trailers and members, with 64 KiB input/output
buffers, a 32 KiB history window and main/secondary Huffman tables. Lookup tests
complete short codes before refilling; failed writes are never replayed by
error cleanup. All 30 codec tests pass Native/Wasm, including one-byte feeds,
long headers, truncation prefixes and I/O failures. The Bytes API adapts to this
path while its caller retains the input. The
[G2 report](../reports/2026-10-24-g2-streaming.md) records direct development
timings and the 8/128 MiB memory comparison. Named replacement and metadata restoration remain
ADR-0004 boundaries. Reject private ReaderBuffer imports, FFI and host gzip
fallback. Replace the inflater only after released public APIs pass optional
headers, multiple members and partial-output error regressions.

Reject a single-document assumption for ordinary jq stdin, textual variable replacement and calling input framing an async blocker. The evaluator's bounded expression surface is not complete jq 1.8.2 modules/streaming/diagnostics.

Reject silently accepting `-C` with plain output, and do not classify explicit
color formatting as an async limitation. Keeping automatic color disabled costs
TTY convenience while preserving deterministic redirected output. Explicit
flags remain available on both backends without adding FFI or delegating to jq.

## Versions and evidence

Baseline: async 0.22.4, x 0.5.5, moonjq 0.1.2; MoonBit 2026-09-20.
The async 0.22.4 refresh does not change the JSON evaluator boundary. It
does enable the independently implemented `base32` command: RFC 4648 uppercase
encoding/decoding, GNU-compatible padding handling and progressive prefix output,
`-d`, `-i` and `-w` are implemented in pure MoonBit with byte-level tests.
As in the pinned GNU implementation, non-zero unused tail bits are accepted;
nonstandard alphabets and locale diagnostics remain outside the support claim.
The `expand` and `unexpand` profiles use byte columns with explicit positive,
ascending stops. This keeps tab conversion independent of terminal width and
locale databases; malformed stops reject before input side effects. Multibyte
display-width behavior remains outside the support claim.
jq tests and unified command contracts cover consecutive values, slurp, raw
slurp, null input, false status and shadowing. Exact-byte color comparisons use
the official jq 1.8.2 executable and cover compact/pretty/indent/key-order output,
raw strings, `-CM`/`-MC` and valid/partial/invalid palettes. Full dependency
resolution uses moonjq 0.1.2 with x 0.5.5 and async 0.22.4.
Historical results remain in [the audit](../reports/2026-09-19-command-fidelity-audit.md).
Candidate runtime results are recorded separately from published versions.

public dependencies only. Versions: MoonBit 2026-09-20, async 0.22.4,
x 0.5.5; core 0.3.0 for the second batch and 0.4.0 for the P2 batch.

## Revisit when

Windows CI requires inline POSIX TZ rules containing filename-invalid `<`, `>`
or `:` to be parsed before a filesystem existence probe. Absolute/explicit
file paths still report their real filesystem errors, and valid named-zone
paths retain file lookup. The original failing fractional-offset contracts and
an angle-bracket DST rule with `/time` remain enabled on all three platforms.

Adopt evaluator features through public APIs only after exact input/output/status
regressions pass. Reopen automatic color when released terminal detection has
Native/Wasm tests covering TTY and redirected streams separately.
