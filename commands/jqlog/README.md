# jqlog

Filter JSON log lines for MoonX.

Version: `cli/jqlog@0.2.8` (development candidate; published baseline: `0.2.7`).

Candidate usage after publication:

```sh
moonx cli/jqlog@0.2.8 [options] <query> [input]
```

## Supported scope

Apply a jq-compatible filter to each valid JSON line and emit compact JSON. Read stdin by default, or pass raw input as the second operand.

The command uses `cli/jq@0.2.10` through its public `engine` package. The parser,
AST, evaluator and filter adaptations are maintained once by jq. Only the JSONL
command adapter remains in `internal/driver`; neither command depends on MoonJQ. See
[third-party notices](THIRD_PARTY_NOTICES.md) for source and license details.

## Limitations

- Invalid JSON lines are skipped. A successful line emits all results as compact
  JSON; a failed line emits none, preserves earlier successful lines and exits 2.
- Filters use jq's current value semantics, including lexical filter/value
  parameters, `elif`, Boolean `and`/`or`, and corrected generator behavior.
  This intentionally replaces the older jqlog evaluator's defect behavior.
- Module loading and the shared `input`/`inputs` cursor remain jq CLI features.
  Imports are rejected; evaluated input and module-metadata requests fail
  explicitly. Filters do not implicitly read later log lines or module files.
- The command's adapter preserves complete grouping/sorting key streams and stable ties. Exact numeric ordering at or above 2^53 remains outside the verified key domain.

The standalone `moonx cli/jqlog` entry and its option meanings remain unchanged:
`-f` selects log input, and the second operand is literal input text. Upgrade
the jq dependency when adopting engine changes; jq-only CLI changes do not
require a jqlog release. Publish the required jq version before jqlog.

## Examples

```sh
moonx cli/jqlog@0.2.8 -f logs.ndjson '.message'
printf '%s\n' '{"level":"info"}' | moonx cli/jqlog@0.2.8 '.level'
```
